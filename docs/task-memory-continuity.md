# 任务记忆接班与隔离（recovered.30）

- 任务按“进行中”（黄）、“未完成”（红）、“已完成”（绿）独立折叠。阻塞、中断、待同步与取消不会因超时消失。
- 完成卡不再十分钟过期。右键“删除任务显示”只持久移除显示，检查点、任务事件和交接记忆保留。
- 同一固定记忆根、同一服务端任务归属的新任务，仅移除自己的紧邻前一个已完成任务显示。未完成任务和其他归属不被取消或清理。模型显示名称不作为身份凭据。
- 固定目录是项目 `.opencode-project/` 或临时 `scratch-memory` 桶中的 `actors/<归属SHA256>/tasks/<任务UUID>/`。工具回执中的 `memory` 是实际定位，不要猜路径。
- 每次任务、进度和提问状态写入原子检查点与追加事件；已关联工具调用记录“未知在途/已收到工具回执”，不据此宣称外部进程已退出。重载的旧执行显示未核实，不自动恢复旧进程。
- 同一记忆根允许多个模型和多个任务，但默认读写各自的私有目录。旧版共享根文件原样保留，不自动混入新执行者；跨历史读取需明确指定来源。
- 右键“复制mcp提示词”复用现有完整连接模板、自定义提示词和手动 HTTP 客户端说明，再附指定任务接班。只在实际 Bridge 已运行时提供地址。地址是敏感信息，仅写入用户剪贴板，不进入任务检查点。
- “复制接班提示词”不含地址，只带任务记忆定位、源任务版本及独立执行要求。新对话先读指定检查点与事件，再在相同记忆根新建自己的任务。不要冒用源 task_id、源归属、写槽或进程。
- 任务卡片右键菜单接入 VS Code 原生 `IContextMenuService`（与聊天区设置菜单一致的深色菜单面板、圆角边框、分隔线与焦点恢复），并同步覆盖 `027-workbench.desktop.main.js` 与 `018-sessions.desktop.main.js`；所有任务工具均支持显式传入 `memory_dir` 或 `task_id` 直接读取指定任务的检查点与记忆（项目记忆与临时记忆通用）。
- 将目标、约束、成功/失败、未知项、待办、下一步及重要证据通过记忆工具保存，换对话前更新交接。只有已提交并成功持久化的事实可恢复；未保存的内部思考、未返回工具结果及历史已被旧版本删除的数据无法凭空恢复。

## 验证范围

`npm run test:task-continuity` 是隔离临时目录中的本地自动测试，不启动应用、不调用任何模型、不连接网络。覆盖持久化、显示清理边界、归属检查、定向复制提示词、项目/临时私有路由和三分组渲染片段。渲染片段测试不是实际 Electron 端到端验收；真实新模型跨对话接班需另外现场验证，编译成功不等于无损接班已达标。
